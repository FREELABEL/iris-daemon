# Rabbit R1 → IRIS

An **OpenClaw-protocol gateway backed by IRIS**. The R1 already knows how to talk to
an OpenClaw gateway at a URL you control; this answers that protocol. Nothing OpenClaw
runs in the path and no Rabbit cloud is called — every turn is served by an IRIS agent.

```
  R1 (LTE)                bridge :3200                    IRIS
  ────────                ───────────                     ────
  push-to-talk  ──WS──►   channels/r1.js
  camera frame            ├─ transcribe ──────────────►   POST /api/v1/transcribe
                          │                                (multipart, glossary-biased,
                          │                                 PHI-gated by bloq_id)
                          ├─ ack (shows the transcript)
                          ├─ agent turn ──────────────►   POST /api/v6/chat/execute
                          │                                 { query, agent_id, session_id }
  speaks reply  ◄──WS──   └─ reply (truncated to 900c)
```

The R1 hosts nothing. Helio P35 / 4 GB / no NPU — it is a microphone, a camera, a
scroll wheel and a speaker. All inference is upstream. That is the whole design.

## Quick start

```bash
# 1. Start the gateway (uses the bridge's existing port — no new port to expose)
node scripts/r1-setup.js start --agent <agent-id> --bloq 639

# 2. Pair the handheld — prints the config to put on the device
node scripts/r1-setup.js pair my-r1 --label "Alex's R1"

# 3. Prove the whole path works, with no hardware
node scripts/r1-simulate.js --device sim --token <token> --dialect native \
  "what is on my plate today"

node scripts/r1-setup.js status     # who is connected, turns, errors
node scripts/r1-setup.js devices    # paired handhelds
node scripts/r1-setup.js revoke my-r1
```

`iris agents list` gives you the agent id.

## Auth: two separate keys, deliberately

| Key | Held by | Used for |
|---|---|---|
| `X-Bridge-Key` | the machine operator | pairing, starting/stopping the gateway |
| per-device token | one handheld | the WS `hello` frame, and nothing else |

A device never carries the operator key. A lost or sold R1 is revoked on its own —
`revoke <id>` — without rotating the key every other tool on the machine depends on.

Only the **sha256** of a device token is stored (`~/.iris/bridge/r1-devices.json`, 0600).
The plaintext is printed once at pair time. Re-pairing the same device **replaces** its
token rather than adding a second live key.

Rejections close with **4401** and send an `error` frame first — on a handheld, a silent
drop is indistinguishable from losing signal.

## Reaching it over LTE

The R1 is not on your Wi-Fi. `r1-setup.js pair` prints the Tailscale address
(`100.64.0.0/10`) alongside localhost — use that one. Do not port-forward the bridge
to the public internet; `daemon/tailscale-address.js` deliberately refuses any address
outside the CGNAT range for exactly this reason.

## The wire format is the unverified part

Everything on the wire lives in **`drivers/r1-dialects.js`** and nowhere else.

| Dialect | Status | Use |
|---|---|---|
| `native` | verified end-to-end | the simulator, first-party clients |
| `openclaw` | **best-effort, unverified** | real hardware |

The `openclaw` mapping was reconstructed from documentation, not from a device. A
protocol guessed from docs fails at the handshake with no useful error, so **do not
fix it by reasoning — capture it**:

```bash
node scripts/r1-setup.js start --agent <id> --dialect openclaw --capture
# point the real R1 at the gateway, press the button once
cat ~/.iris/bridge/r1-frames.jsonl
```

Every raw inbound frame is appended verbatim (audio/image payloads redacted — they are
megabytes of base64 and say nothing about the format). That file is the specification.
Complete `openclaw.decode` from it.

Undecodable frames are captured **even with `--capture` off**, because the first frame
that fails is the most valuable one and it only arrives once.

**A green simulator is not a working R1.** The simulator proves the IRIS path — pairing,
WS, transcription, agent, reply. It cannot prove the dialect, because it implements the
encoder a second time rather than importing the server's (if it shared that code, a
wrong dialect would agree with itself and pass against a format no hardware speaks).

## Two agent modes

```
chat     (default) → POST /api/v6/chat/execute { query, agent_id, session_id }
channel            → POST /api/v6/channels/r1  (UnifiedChannelController)
```

`POST /v6/channels/{channelType}` is already a catch-all for YAML-defined channels and
`r1` matches its pattern — but it only resolves to an agent once a channel record exists
server-side, and until then it answers 200 with nothing useful. So the default is the
mode that needs no server-side change. Don't flip it without checking the record.

`session_id` is `r1:<device-id>`, so context carries across button presses.

## PHI

Pass `--bloq <id>`. `bloq_id` is what applies the transcription PHI policy: if that bloq
is marked as containing PHI the endpoint returns **422 rather than sending the audio to
a cloud provider**. That is the correct outcome, not a bug to route around — capture
on-device instead. Omitting `bloq_id` is permitted but logged server-side as unprotected.

## Tests

```bash
node --test tests/r1-channel.test.js     # 11 tests, real bridge process, stubbed IRIS
VERBOSE=1 node --test tests/r1-channel.test.js
```

Boots an isolated bridge (own `HOME`, own port) against a stub iris-api and drives it
with a real WebSocket client. Pairing, handshake, dialect decode, transcription
multipart shape, the agent call, reply truncation, revocation and token rotation all
execute for real. IRIS is stubbed so the suite doesn't depend on prod credentials or on
an agent id that may move.

## Files

```
drivers/r1-dialects.js    wire formats + frame capture   ← the only format-aware file
drivers/r1-openclaw.js    WS gateway, sessions, heartbeat, auth
channels/r1.js            transcribe → agent → reply
lib/r1-devices.js         pairing registry (sha256, timing-safe)
scripts/r1-setup.js       pair / start / status / devices / revoke / stop
scripts/r1-simulate.js    a fake handheld
tests/r1-channel.test.js  end-to-end
```

HTTP surface (all behind `X-Bridge-Key`):

```
GET|POST|DELETE  /api/providers/r1
GET|POST         /api/r1/devices
DELETE           /api/r1/devices/:deviceId
```

## Known limits

- **`openclaw` dialect unverified** — the one thing hardware must settle.
- **No streaming.** One reply per turn, truncated to 900 chars. A 2.88" screen and a TTS
  voice both punish a wall of text.
- **No TTS here.** We return text with `speak: true`; the device speaks it. `iris voice`
  manages agent voices if server-side synthesis is wanted later.
- **Battery.** ~3.5 Wh. This is a push-to-talk device, never an always-listening one.
- **Buy new.** The MT6765 bootrom hole that gives you root also lets a previous owner
  persist malware.
